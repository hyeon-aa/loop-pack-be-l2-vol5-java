# 5주차 설계 — 테스트 PG 연동

현재 커밋까지 포함된 구현을 기록한다.

- 주문·예약·결제 시도의 상태와 전이 모델
- 결제 시도·관찰 이력의 JPA 저장과 유일 제약
- 응답 유실·지연·오류와 거래 상태를 제어하는 가짜 PG
- PG HTTP 생성·조회, timeout과 생성 재시도 차단
- 조회만 감싸는 retry·회로·fallback과 다음 시도 시간 예산
- PG 제공자 빈·HTTP·조회 정책 설정
- PG 주문 confirm·reconcile, TX A·B·C, 재고 반환과 과거 POINT 주문 보존
- callback 본문 대신 PG 조회로 결과를 확인하는 API
- 10분 지난 미완료 결제의 복구 배치
- 비교 실험 전용 experimentTest 작업
- 설정·순서·연결 자원에 관한 비교 실험: 3개 추가

결과를 모르면 예약을 유지하고 기존 거래를 조회한다. 생성 POST는 다시 보내지 않는다. 확실한 미발송은 별도로 실패 처리한다.

## 검증 범위

추가된 테스트와 실행 결과는 [구현 기록](implementation-log.md)을 따른다. 아직 추가되지 않은 테스트를 현재 커밋의 검증 결과로 보지 않는다.
